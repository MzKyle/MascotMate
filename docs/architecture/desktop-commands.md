# 桌面命令队列

陪伴控制台和皮肤商店的本地 HTTP helper 共用应用数据目录下的 `commands-v1/`。单独保留每条命令和结果，沿用 Godot 的 350 毫秒轮询。Godot 不运行时，已接收的请求可以留待下次启动处理。队列使用随应用打包的 Python 标准库和 Godot 文件 API。

## 接收与执行

- Python 在跨线程和跨进程的文件锁内分配序号。命令 ID 由带前导零的序号和随机后缀组成。Python 写完临时目录中的 `request.json` 并同步文件后，将整个目录重命名发布。HTTP 202 表示接收成功，执行顺序以发布顺序为准。
- Godot 逐个处理命令。它将 `pending` 改名为带开始时间的 `running` 标记以取得执行权。设置类命令在保存并应用设置后记录结果。皮肤启用先加载可播放的动画，再保存选择。AI 检查和记忆总结等待异步调用结束。回放成功表示结果已写入，场景断言结果由回放页面展示。
- 通过带原有会话 token 的 `GET /api/commands/{id}` 查询内部回执。结果可为 `pending`、`running`、`succeeded`、`failed` 或 `expired`。回执记录接收、开始及完成时间与失败原因。Godot `--verbose` 日志记录接收后开始执行的命令、耗时和结果。失败和中断也会写入常规警告日志。
- 待开始命令的有效期为 120 秒。超过有效期后，helper 或 Godot 尝试把 `pending` 原子移动为过期标记。若 Godot 先取得执行权，会在调用业务代码前再检查期限。前端等待较久时提示暂时无法确认，并继续查询及刷新业务状态。

## 中断与清理

已领取的命令每个 ID 最多调用一次处理器。发布结果前发生崩溃时，业务改动可能已经生效。运行标记满 20 秒仍无结果时，记录中断和结果未知，释放队列并继续处理后续命令。若运行中的进程随后退出，未领取的命令在有效期内可交给下一次启动。回执发布因临时 I/O 故障失败时，仅重试发布结果。保留期内，已完成 ID 下重复出现的待执行标记会被跳过。

队列同时允许最多 128 条待处理或运行中的记录和 512 条总记录。每份请求或结果 JSON 上限 4 KiB。超出容量时 HTTP 请求明确被拒绝，已安装皮肤仍保留。helper 运行时定期扫除超过 30 分钟的终态记录，下次启动 helper 时也会清理历史记录和未发布的临时目录。文件同步和重命名能应对进程退出，中断时磁盘内容仍取决于系统缓存与文件系统行为。

旧版 `companion_console_command.json` 和 `skin_store_command.json` 保留在原处并在启动时记入警告日志。旧协议缺少可靠回执，升级后只消费新队列。Godot、helper 和网页使用同一套版本。
